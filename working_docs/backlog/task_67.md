## Verified target command graph

- Root `package.json` currently composes `test` serially as `test:unit && test:api && test:integration`. The three tier commands hard-code package filters: unit names contracts, logger, mock ERP, worker, web, and load orchestrator; API names only `api`; integration names DB and worker. A new package or newly supported tier is invisible until this central list is edited.
- Those root tier commands call the package scripts in `apps/{api,load-orchestrator,mock-erp,web,worker}/package.json` and `packages/{contracts,db,logger}/package.json`. The package scripts and their adjacent Vitest configs already know the real membership: contracts/logger/web/load-orchestrator use `test/**/*.test.ts`; mock ERP and worker unit use `test/unit/**/*.test.ts`; API uses `test/**/*.test.ts`; DB and worker integration use `test/integration/**/*.test.ts`. API, web, DB, and worker integration scripts also apply `scripts/run-with-test-env.mjs` where required.
- Root `test:watch` does not traverse that graph. It invokes root `vitest.unit.config.ts`, whose sole include is `packages/{contracts,logger}/test/**/*.test.ts`; all app unit suites are omitted. Watch must remain a long-running local command and must not accidentally run API or infrastructure suites.
- Root `test:coverage` builds shared packages and then chains six filtered unit invocations with `&&`. It omits `apps/api/vitest.api.config.ts`, `packages/db/vitest.integration.config.ts`, and `apps/worker/vitest.integration.config.ts`. Each process creates an independent V8 report relative to its package; there is no declared threshold, no aggregate manifest, and the fail-fast shell chain hides later failures after the first non-zero exit.
- Root `turbo.json` declares `^build` dependencies and empty outputs for all three test tiers, but does not set `cache: false`. Empty outputs do not make environment-dependent API/integration results safe to replay: those tasks depend on mutable PostgreSQL, Redis, BullMQ, ports, and test environment. There is no checked-in `.github/workflows` directory, so no current CI job establishes infrastructure, invokes coverage, publishes reports, or tears infrastructure down. The implementation must make the commands CI-ready but must not claim CI enforcement until a caller is actually added.

## Required implementation shape

1. Make the workspace package the source of truth for tier membership. Add consistent package-local scripts for only the tiers each package genuinely owns (for example `test:unit`, `test:api`, `test:integration`, their watch counterpart where applicable, and coverage counterparts). Change root unit/API/integration entry points to unfiltered Turbo discovery. Do not add empty tier scripts with `--passWithNoTests`: absence should mean non-membership, and a declared tier with no matching files should fail visibly.
2. Make `test:watch` discover every package-local unit-watch script, including contracts, logger, mock ERP, worker unit, web, and load orchestrator. Configure the Turbo watch lane as `persistent: true` and `cache: false`, preserve each package's working directory/config/environment wrapper, and exclude API, DB integration, and worker integration suites from the default watch command. Provide a bounded run-mode/static way to verify membership; automated checks must never launch an indefinitely persistent watcher.
3. Split coverage into honest, named package-local lanes and compose them at the root. The default coverage gate must include all unit suites plus the API suite, DB integration suite, and worker integration suite; it must preserve `build:shared`/`^build` ordering and the existing test-environment wrappers. If a fast unit-only coverage command is retained, name it explicitly so it cannot be mistaken for the full gate.
4. Define and enforce an initial, repository-owned V8 coverage floor for statements, branches, functions, and lines. Put the threshold policy in a shared Vitest coverage config/helper imported by every coverage config, or use a deliberately documented per-package policy; do not duplicate drifting numbers across eight configs. Prefer a modest ratchet based on the verified baseline rather than excluding difficult files until a high percentage passes. Exclusions may cover generated output, declarations, framework artifacts, and test/config files, but not API orchestration, Redis Lua/DB invariants, concurrency logic, or BullMQ worker paths named by this task.
5. Keep coverage artifacts collision-free and diagnosable. Give each package/tier a distinct reports directory and emit at least text plus a machine-consumable format suitable for later CI aggregation. If the floor is intended to be repository-global, merge coverage before threshold evaluation; do not describe independently passing package floors as a global aggregate. If independent floors are chosen, state that contract clearly and ensure every required tier is gated.
6. Make execution semantics explicit. Coverage is a bounded run task, never persistent and never cached. API/integration/coverage tasks must use `cache: false`; unit run caching may be retained only if inputs and environment are correctly represented. Avoid a shell `&&` chain that suppresses all later package results: let Turbo schedule independent package coverage tasks and aggregate their exits. Preserve dependency builds through `^build`, but do not serialize unrelated packages unnecessarily. Infrastructure-backed suites must not race against reset/migration or teardown; the full local command may require already-running clean test infrastructure, while a separate orchestration command may own up/migrate/run/down with cleanup on failure.

## Local and CI contract

- `pnpm test:watch` is the developer feedback loop for every unit suite and stays alive until interrupted. It must neither start containers nor include infrastructure/API tiers.
- `pnpm test:coverage` is the bounded, authoritative full coverage gate. It must return non-zero when any required suite fails, any required suite is undiscovered, or the selected coverage floor fails. Its help/README text or script naming must clearly state the test-infrastructure prerequisite if lifecycle setup is not included.
- A later CI caller should use the same root coverage command, provision PostgreSQL/Redis, apply test migrations/reset in the repository-prescribed order, retain all per-tier reports even when one task fails where the runner permits, and always tear down. This task may add the smallest script/config support needed for that contract, but adding a new CI platform/workflow is not required because none exists in the target tree.
- Do not cache or restore infrastructure-backed test successes across jobs. Coverage artifacts are outputs for collection, not evidence that Turbo may skip executing the gate.
