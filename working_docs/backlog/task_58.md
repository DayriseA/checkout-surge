## Rollout and compatibility

- This is a breaking wire change even though Redis Pub/Sub is ephemeral: independently deployed API publishers/subscribers and open browser tabs can overlap. Prefer an explicit contract-versioned cutover or a bounded dual-read window. During dual-read, emit one canonical event and let consumers accept both shapes; do not dual-publish because aggregate replacement and per-order deltas would double-apply. Remove legacy reads only after all publishers and web assets are deployed.
- Unknown event categories, business names, and metric names must fail schema validation and produce bounded observability (category/name, correlation/run identifiers, and parse/publish stage). They must not crash Redis subscription/fanout or alter the durable business operation. Do not silently coerce an unknown event into `business.outcome.updated` or a generic metric.
- Decide `eventId` per semantic category, not globally. It is unused for current projection snapshots and may be removed there, but task 47 requires a stable durable transition ID for per-order deduplication; `business.event.recorded` should preserve its durable event ID. Do not generate a fresh UUID on each retry for a logical transition. Document whether snapshot/metric observations have an observation ID and what, if anything, consumers deduplicate.
- Keep `/dashboard/recovery` authoritative. SSE remains advisory and non-replayable; after reconnect, version mismatch, parse drop, or missed event, recovery repairs state. Preserve the current recovery baseline/current-run/current-sale-offer filtering.
- Update generated-script names and parser recognition atomically. If old k6 processes can outlive deployment, accept both old and canonical counter names temporarily but normalize to one internal counter and guard against counting both aliases in the same run; otherwise explicitly require restarting active runs at cutover.

## Focused verification

- Contract tests: accept each of the four public categories and every business/metric literal; prove each metric's value/unit/dimensions constraints; reject unknown category/name, wrong metric unit, malformed identity, and category/payload mismatches.
- Producer tests: assert API/finalizer/task-27/task-47 publishers produce the canonical category and exact payload after the relevant commit/inspection; retry tests prove stable per-order event identity and no duplicate logical publish.
- Redis/SSE tests: canonical events survive serialize/parse/fanout; malformed and unknown events are reported and isolated; compatibility-window fixtures cover the chosen legacy read policy.
- Web reducer/recovery tests: each canonical category updates only its intended projection; stale, wrong-run, wrong-sale-offer, duplicate, and regressive per-order events are ignored; terminal load-run events still trigger final recovery.
- Load-orchestrator tests: generated script contains the three canonical counter names and no legacy singular names; accumulator fixtures count canonical sold-out/unexpected points, ignore unrelated metrics, and (only if selected) normalize legacy aliases without double counting.
