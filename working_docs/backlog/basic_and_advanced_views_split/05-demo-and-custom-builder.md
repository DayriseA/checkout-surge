# Task 05 — Demo chooser and custom builder

Status: Done (2026-09-16) · Depends on: [Task 04](04-public-run-report.md) · Next: [Task 06](06-public-run-history.md)

## Outcome

Visitors can choose and start a simulation with little reading. The custom builder stays available in both views behind a local disclosure, and neither switching views nor collapsing the builder discards custom settings or conceals the reason a start cannot proceed.

## Work

1. Shorten the entry explanation to the simulated flash-sale experiment and rewrite the page subtitle under the h1 in plain vocabulary. Place the recommended Preview 1k card and its Start action in the first ready desktop viewport; keep all four current public presets available, including Surge 10k and the duplicate experiment. No preset values, recommendation slug or backend policy changes.
2. In Basic cards keep name, buyers/attempts, stock, one distinguishing behavior/learning goal and Start. The duplicate experiment says each buyer tries twice. Move ERP capacity/delay, exact duplicate accounting, expected sold-out totals and detailed assumptions to Advanced. Keep any duration hint qualified; do not turn the report's measured 31 seconds into a new estimate or guarantee.
3. Consolidate shared availability near the actions: ready, shared simulation running, starting, start uncertain, cooldown, unavailable or incomplete recovery. Preserve authoritative readiness, budget, public visitor and duplicate-submission gates and accepted-ID navigation to Watch. Full service/budget/retry mechanics may be Advanced, but the blocking reason and valid next action stay Basic.
4. Keep the existing builder as a local “Customize a scenario” disclosure below the presets in both views. Opening it does not change the page's view mode. In Advanced it may be expanded by default; in Basic it is collapsed. Keep the existing form and nested protection settings with all supported spike/steady-traffic, stock, duplicate, ERP and safety controls.
5. **The builder must stay mounted whenever it is not visible**: collapse or hide it with the `hidden` attribute (or the disclosure's closed state), never by unmounting the form subtree. Field-level native validation errors live in each `LabeledInput`'s local state ([public-demo-entry.tsx:1287](../../../apps/web/src/app/components/public-demo-entry.tsx)), and the nested protection disclosure's open state is DOM state; both are lost on unmount. The draft itself already lives in `PublicDemoEntry`. Starting a preset still submits that preset; it must not silently apply the collapsed custom draft. A collapsed builder with an edited draft shows a concise retained-settings notice next to the disclosure.
6. Preserve semantic form submission by button or Enter and current client/server validation. When a custom submission error arrives while the builder is collapsed, open the disclosure and the relevant nested disclosure, then focus the error summary/field. Preserve values. For inactive spike/steady fields, retain existing rules that omit inapplicable payload values and clear inapplicable errors; do not resurrect them merely because the view changed.
7. Keep operation-level errors public-safe and distinct from field validation. Missing policy/presets/readiness must disable only the capabilities the current gate allows; do not render an empty chooser as ready.

## Acceptance criteria

- A new visitor sees a recommended Start action at about 1536 × 720; mobile cards are easy to scan and operate.
- All current public presets start through the existing path, with unchanged payload and navigation semantics.
- The builder contains every current custom control and field constraint in both views. Steady rate × duration remains attempts, never implied distinct buyers.
- Repeated view changes and collapse/expand cycles retain the edited draft, selected traffic pattern, open nested disclosure and field errors, because the form is never unmounted. No switch submits a run or resets recovery/readiness polling.
- Hidden-field backend/native validation can be reached and corrected with keyboard focus, including a response that arrives while the builder is collapsed.
- Conflict, reset, budget, uncertain-start and unavailable states remain clear in Basic and cannot enable invalid duplicate starts.
